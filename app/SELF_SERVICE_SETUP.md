# Self-Service Setup

Organizations must be able to configure and maintain the application without product-owner assistance.

## Setup Wizard

The initial setup wizard should guide an organization administrator through:

1. Organization profile
2. Language
3. Terminology
4. Definitions
5. Roles
6. Permissions
7. Users
8. Services
9. Zones
10. Resources
11. Teams
12. Availability
13. Scheduling rules
14. Travel rules
15. Appointment statuses
16. Notifications
17. Integrations
18. Branding
19. Review
20. Activation

## Progress

The setup wizard should show:

- Completed sections
- Incomplete sections
- Required configuration
- Optional configuration
- Configuration warnings

## Configuration Validation

Before activation, the system should check for common configuration problems.

Examples:

- No administrator
- No service
- No resource
- Missing availability
- Invalid scheduling rules
- Invalid travel settings
- Missing integration credentials
- Conflicting configuration

## Ongoing Administration

After setup, administrators must be able to modify configuration without contacting the product owner.

Changes should take effect without requiring code changes or application reinstallation.

## Guided Help

Each configuration area should provide concise explanations and definitions.

Organizations should be able to customize terminology without changing the underlying system behavior.

## Safe Defaults

The application should provide sensible defaults so an organization can complete setup without understanding advanced configuration.

Advanced settings should remain available for organizations that need them.

## Configuration Recovery

Administrators should be able to identify and correct configuration problems through the System Health and Configuration areas.

## No Required Product-Owner Intervention

Normal setup, configuration, troubleshooting, and maintenance must not require the product owner.
