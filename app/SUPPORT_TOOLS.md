# Support Tools

The product must provide self-service troubleshooting tools.

## System Health

Administrators can view:

- Application status
- Database status
- Integration status
- Sync status
- Failed jobs
- Notification failures
- Recent errors
- Application version
- Configuration warnings

## Problem Reporting

Users can report problems from inside the application.

Reports should automatically include safe diagnostic information.

## Error Identification

Errors should have a unique reference number so administrators can identify the problem without technical knowledge.

## Integration Troubleshooting

Administrators can:

- Test connections
- View last successful sync
- View failed syncs
- Retry failed syncs
- Run a manual sync
- Reconnect an integration

## Scheduling Troubleshooting

Administrators can validate:

- Availability
- Travel rules
- Team assignments
- Resource assignments
- Scheduling conflicts

## Configuration Validation

The system should identify incomplete or contradictory configuration.

## Help

Contextual help should be available throughout the application.

Help should use the organization's configured terminology where appropriate.

## Documentation

Core product documentation should be maintained within the application.

## Safe Repair

Where possible, common problems should have administrator-accessible repair actions.

Destructive actions require confirmation.

## Product Owner Independence

Routine troubleshooting should not require contacting the product owner.
